# SPEC-005 tasks

| Task | Given | When | Then |
| --- | --- | --- | --- |
| 005-01 | The accepted starter and pinned SDK | Verify format, analyze, run starter tests and exercise the release build configuration | The checks pass, release signing requires an explicit private key, and each pushed task generates a Mission Control preview artifact |
| 005-02 | The Android release on phone and tablet | Open the home, lesson and learning tools offline in the supported sizes and orientations, including increased text size | Arabic and controls remain reachable, with screenshot and accessibility evidence |
| 005-03 | Fresh installs and existing saved preferences | Use lesson and challenge actions with effects enabled or disabled, and use the app with speech disabled or unavailable | Four short offline cues are distinct, gentle and peak-limited. | 005-04 | An owner-accepted candidate | The owner supervises a child trying lesson navigation, feedback and continued practice | An anonymized owner record describes independent actions, assistance, comfort and follow-up |
| 005-06 | The signed candidate on physical Android | Exercise airplane mode, both orientations, lesson navigation, mascot reactions, backgrounding and cold restart | Progress and preferences survive, and actual hardware observations and screenshots establish whether the low-end gate is met |
| 005-05 | Two signed builds with increasing Android version codes and a compatible pack revision | Install over the populated baseline, exercise all four worlds, inspect persistence and the package, and run the final regression and platform builds | Learning state and attempt history survive. What's New identifies the pack update. Only the approved six lessons ship, and privacy and signing checks pass |

The owner playtest is a separate milestone. The connected tablet may supply physical evidence while the designated low-end gate remains open if that hardware is unavailable. Track both outcomes explicitly.
