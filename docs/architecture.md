# Architecture
Flutter stable installed locally (record actual versions, no guessed version); Riverpod, GoRouter, feature-first modules: app, design_system, worlds, lesson, challenges, progress, parent, audio, content. Flutter widgets rather than Flame. Choose a maintained local persistence solution after checking platform compatibility; record ADR. No network requirement for core. Platform TTS Arabic MSA if available offline; optional bundled reviewed narration later. User controls speech/effects independently.
## Responsive layout
Logical width <600 compact single column, 600–839 medium, >=840 expanded tablet: two-pane world/path or question/choices where useful; constrain readable content width, avoid stretching cards. Test 390x844, 600x960, 800x1280, 1024x768 and text scale 1.3/2.0. SafeArea, RTL directional padding, minimum 48 logical px target, focus and semantics, no color-only feedback. Tablet landscape is a proposed default design target, not a forced orientation.
## Data
Stable IDs; curriculum version; world > unit > lesson > facts/challenges. Question type discriminated union; options stable IDs; source references with locator, title, authenticity/review note where applicable. Review state draft/approved/rejected; approval recorded with content hash, reviewer/date. Validate schema, references, supported types, answers and approval hash; fail closed in release. Progress keyed by stable lesson/question ID; atomic writes, migration and reset confirmation. XP once per first completion plus bounded review reward; stars based on first-attempt accuracy (1/2/3 at completion, >=60%, >=90%); unscored cards excluded. Review due on next session after error, then 1/3/7 days after success (proposed). Persist local day, not punitive streak.

## Challenge engine

- Definitions and validation use a versioned, discriminated JSON shape with stable challenge and option IDs. Evaluation is pure Dart and accepts IDs independent of presentation order. Widgets own presentation. An optional illustration reference is resolved against local assets.
- A session will hold immutable state for phase, ordered IDs, current challenge, attempts and completion. The persistence interface will store that state and award completion and unlocks in one idempotent transaction. First-attempt correctness stays separate from eventual success. Unscored activities have no effect on accuracy. A zero-scored result has absent accuracy. Review will visit each missed scored challenge at most once per session.
- Reading-only lessons retain reading completion. For a lesson with required challenges, final reading advances to the challenge session. Completion requires reaching results after the required activities. Keep preview progress and future attempts in a separate storage scope from approved content, even when IDs collide.
- Editorial changes may keep the same stable lesson and objective identity. The existing reading index resets when its content version changes, while earned completion remains. Keep earned history after learning objectives change and require new evidence for a new objective revision. Resume in-flight sessions only across explicitly compatible objective, challenge and option identities with known order. Milestone 003-04 will implement that session policy without deleting prior completions.
