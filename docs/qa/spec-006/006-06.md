## Install and launch

Build with `scripts/build_adventure_playtest.sh` from the Flutter checkout. The APK is `build/playtest/noor-adventure-0.2.0.apk`. Install it alongside Noor and open **نور — المغامرة**. The launcher opens the Worship map. The highlighted fountain starts W06 and the speaker button controls effects.

The release-mode APK uses `dev.noor.noor.adventure`, version 0.2.0 build 1, and the Android development key for local sideloading. Android provides it a separate data directory and a fresh first install. The existing signed Noor app remains `dev.noor.noor`. The playtest build exposes only the W06 adventure routes. It validates the signed bundle using the existing approval ledger and exact W06 bindings. The bundled starter pack files match the approved release bytes. The APK requests no network permission.

APK SHA-256 `31ffc2be2fa21deb1bae8f90babb7ecc31f7d0099e844ac04cdfe2f6f89cb8d1`.

## Observe during the supervised playtest

1. Open the app and let the child choose where to tap. Note whether the fountain and the first interaction are easy to find before offering help.
2. Watch for confusion between washing and wiping, attempts to skip ahead, and whether Noor’s feedback helps the child recover. Note where the child switches between drag and tap.
3. Let the child try the ordering challenge independently. Note what made the ordering clear, how the retry hint was used, and any help you gave.
4. Watch whether the child opens the chest, finds the collection again, or chooses to replay. Note any Arabic, sound comfort, touch, rotation or pacing friction.
5. Record the build number and anonymous observations. Stop when the child wants to stop.
